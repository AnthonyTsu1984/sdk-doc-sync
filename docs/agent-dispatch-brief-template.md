# Agent 派发任务书模板（预算纪律五件套）

状态：现行（切片 3-1 引入）。派发任何 subagent 前按本骨架填任务书；缺件不派。
配套计量：`node scripts/agent-budget.js --live`（在途回合/代理）· `--ledger`（销账台账）· `--status <id>`（单代理视图）· `--settle <id>`（完成后机械销账）。

## 为什么必须有这五件套（2026-10-15 实证）

同日四起预算超支，最重一次 **actual 3573 万 vs budget 400 万（8.9 倍）**，另有两例 2200-3600 万区间（回合数 172/222）。复盘定论：

- 根因不是单点事故，是**代理对自身消耗与回合数零感知**——四起超支的自停条款四度未触发，代理在无预算反馈的环境里把"再查一步"重复了两百多回合；
- 成本模型已定论：**总消耗 ≈ 回合数 × 上下文规模**。回合数是第一杠杆：上下文每回合全量重读，回合数线性放大一切；
- 大宗数据过上下文是第二杠杆：一次 `cat` 全量 fixture 就能把单回合上下文顶到数十万 token。

派发器（你）是代理唯一能拿到预算反馈的通道：任务书里不写，代理就不知道。派发后用 `--live` 盯回合数，完成用 `--settle` 机械销账，把"自觉"换成"计量"。

## 任务书骨架（复制后填空）

```markdown
你在 <repo 绝对路径> 工作。任务：<一句话交付物>。

## 预算纪律（不可协商）
- 预算 **<N 万，默认 300 万> token / 回合上限 <N，默认 30>**。
- 开工先列实现计划再动手；每完成一件即 commit。
- 大宗数据禁过上下文：fixture/语料/快照一律脚本复制到工作区后**抽样 ≤10 条**查看，
  禁止 cat/head 整文件；查证据用 grep/python 摘要，不整读。
- 先落袋：中间产物随做随写盘（指定路径），报告只引用路径不粘贴大宗内容。
- 自停条款（满足其一立即收尾报告，禁止"再查一步"）：
  1. 回合数达到 <25（上限 30 的 80% 预警线）；
  2. 同一问题连续 2 次尝试未推进；
  3. 发现任务范围超出任务书——停下写清剩余方案报回，不自行扩界；
  4. 关键输入缺失/不可达——如实报告失败，不猜测续接；
  5. 交付物+测试已绿——立即收尾，不做"顺手优化"。

## 交付
- 改动落 <worktree/分支>；最终消息给：<提交清单/测试数字/决策清单/边界>。
- 可用 `node scripts/agent-budget.js --status <你的 agentId 前缀>` 自查消耗。
```

## 派发器操作规程

1. **派发前**：任务书填满五件套（预算/回合上限/先落袋/大宗数据禁令/自停条款）。范围含糊的任务先切小再派。
2. **在途**：`agent-budget --live` 盯 ROUNDS/TOKENS 列；出现 `ROUNDS>30` 或 `TOKENS>300万` 旗标即准备介入（停止/改派），不等代理自觉。
3. **完成**：`agent-budget --settle <agentId> --budget <派发预算>` 机械销账进 `tmp/token-budget-ledger.jsonl`；回填 budget 后 `--ledger` 直接读 variance。
4. **超支**：不粉饰。actual 落账、根因一行写进 note，回流到本模板的实证段。
